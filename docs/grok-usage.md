# Grok 订阅用量说明

本文是对 Grok 模块取数与展示行为的补充说明，不替代项目 README。

## 当前实现查什么

CodeBar 的 Grok 模块读取本机 `~/.grok/auth.json`（或设置中的自定义目录），查询订阅共享池的已用百分比和重置时间。

这与以下两项不是同一套额度，请不要混读：

- xAI API 预付余额或模型速率限制（官方 Management API / `api.x.ai`）
- Grok Bot 周用量（在未统一到 The X Subscription 时，可能是另一套计量）

官方公开文档只说明在 grok.com 或 App 的 Settings → Usage 中查看订阅用量，没有把订阅周池查询发布为稳定公开 API。CodeBar 使用的是官方 Grok CLI `/usage` 的同源路径：

`GET https://cli-chat-proxy.grok.com/v1/billing?format=credits`

该接口可能随官方 CLI 变化。界面里的“数据来源”会标明这一点。

## 周期与百分比

- 若响应包含 `currentPeriod.type`，按类型显示“周额度”或“月额度”。
- 旧响应没有周期类型时，显示“当前周期额度”，条目键仍为 `grok.weekly`，以兼容已保存的模块配置。
- 用量保留接口返回的小数百分比，例如 `6.4%`，不会先取整再反算剩余。
- 周期重置后，接口可能省略为零的百分比字段。若周期类型完整且起止时间有效，会显示 `0%`，并说明这是查询成功，不是失败。

## 附加字段

只有响应里真正出现的数据才会展示：

- `productUsage` 中的已命名产品拆分；若某产品没有 `usagePercent`，显示“无数据”，不编造 0%
- 大于 0 的 `prepaidBalance`
- 大于 0 的按需用量或上限

不会为缺失字段编造 0 值或产品列表。无名产品行会被忽略。

## 失败、限流与缓存

- 查询成功且用量为 `0%`：正常结果，不是错误。
- HTTP 429：进入冷却（默认 5 分钟，或遵守 `Retry-After` 的秒数 / 标准 HTTP-date），冷却期内不再发请求。令牌刷新接口的 429 使用同一套冷却。错误文案会说明这是限流，不是用量为 0。
- 查询失败时，若已有上次成功结果，会保留并改写刷新状态为“上次成功结果（旧缓存），不是本次查询”，不再显示“订阅用量已更新”。错误提示会说明“可能不是当前用量”；若上次重置时间已过，会额外提示不要把过期周期当作当前额度。

OAuth 即将过期或订阅接口返回 401 时，仍只刷新一次令牌。授权被撤销后需要先在 Grok 重新登录。
